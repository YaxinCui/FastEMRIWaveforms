## 1. 现代 GPU 硬件架构与算力断层剖析

### 1.1 Turing 架构（RTX 2080 Ti, SM 7.5）与计算单元配比
在消费级与多数工作站 GPU 上，FP64 双精度单元被严重精简，而 FP32、FP16 和 Tensor Core 提供了压倒性的算力：

| 计算单元类型 | 数量 / SM (Turing TU102) | 算力特点 | 适用阶段 |
| :--- | :--- | :--- | :--- |
| **FP64 核心** | **2 个 / SM** | 极低吞吐（仅为 FP32 的 $1/32$） | 轨迹积分、长时间相位、高精度规约 |
| **FP32 核心** | **64 个 / SM** | 吞吐高，单指令多数据（SIMD）原生加速 | 振幅插值网格、SWSH 谐波评估、坐标转换 |
| **INT32 核心** | **64 个 / SM** | 可与 FP32 核心并发执行（独立数据通路） | 地址计算、样条多项式索引寻址 |
| **Tensor Core** | **8 个 / SM** | 混合精度矩阵乘累加（MMA, FP16/BF16/TF32 输入，FP32 累加） | ROMAN 神经网络密集全连接层 |

### 1.2 瓶颈定性：算力受限（Compute-Bound）vs 带宽受限（Memory-Bound）
* **算力受限内核（Compute-Bound）**：计算访存比（Arithmetic Intensity, FLOP/Byte）高，如密集的矩阵乘法（GEMM）、复杂多项式求值。
* **带宽受限内核（Memory-Bound）**：计算访存比低，如数组搬运、简单的向量加法、无重用的大规模 2D/3D 插值表查询。
* **加速准则**：
  * 对于 Memory-Bound 的插值与系数查找，降低存储精度（FP64 $\to$ FP32）直接**将访存量减半**，性能提升往往比单纯提升时钟频率更显著！
  * 对于 Compute-Bound 的神经网络，使用 Tensor Core 进行分块矩阵乘能够释放数倍的理论峰值。

## 2. 混合精度（Mixed Precision）分层策略

FEW 是多模块协同流水线，各模块对精度的敏感度差异巨大：

```
[ 动力学轨迹与相位 (FP64 刚性锁定) ]
      │ (p, e, ι, Φ) - 毫厘之差将在数十万圈后发散
      ▼
[ 振幅生成与插值 (FP32 候选) ]
      │ A_{lmkn} - 能量微弱的高阶模式对绝对相位无影响
      ▼
[ 模式加权与求和 (Double-Single / 补偿累加) ]
      │ ∑ A * Ylm * exp(iΦ) - 避免成千上万项相加时灾难性相消
      ▼
[ 最终引力波应变 (FP64 / complex128) ]
```

### 2.1 为什么动力学与时间步进必须死守 FP64？
* EMRI 信号在一年内包含超过 $10^5$ 弧度的相位演化。
* 若步长截断或累加精度为 FP32（相对精度 $\epsilon_{\text{mach}} \approx 1.2 \times 10^{-7}$），经过 $10^5$ 步后相位漂移可达：
  $$\Delta \Phi \sim 10^5 \times 10^{-7} \sim 10^{-2} \text{ rad}$$
  这足以造成明显的波形去相关（Dephasing），导致参数估计偏差。因此，自适应 ODE 步进器（DOP853）必须始终在 FP64 下运行。

### 2.2 为什么振幅插值网格非常适合 FP32？
* 引力波的主要能量集中在少数几个低阶主导模式上（如 $(2,2,0), (2,1,0)$ 等）。
* 大多数处于边缘的高阶模式，其振幅比主导模式小 $3 \sim 6$ 个数量级。对这些模式的振幅采用 FP32 评估，其绝对误差通常在 $10^{-10}$ 以下，对整体波形信噪比与重叠度（Match）的影响完全处于 $10^{-12}$ 量级，远在检测极限之内。

### 2.3 Double-Single（双单精度）与补偿求和算法
当硬件缺乏原生 FP64（如部分着色器或嵌入式单元），或希望在 FP32 单元上获得接近双精度的累加质量时，可采用 **Double-Single（DS）** 算法：
* 一个数值由两个单精度浮点数表示：$x = x_{\text{hi}} + x_{\text{lo}}$，其中 $|x_{\text{lo}}| \le \frac{1}{2} \text{ulp}(x_{\text{hi}})$。
* 有效尾数长度达到 $24 + 24 = 48$ 位（标准 IEEE-754 双精度为 53 位）。

**无误差变换核心（Knuth TwoSum 算法）**：
```c
// 在 GPU 内核中实现两个 float 的精确加法与残差提取
__device__ inline float2 two_sum(float a, float b) {
    float s = a + b;
    float v = s - a;
    float e = (a - (s - v)) + (b - v);
    return make_float2(s, e); // s 为高位近似，e 为精确舍入残差
}
```

**Kahan 补偿求和（Compensated Summation）**：
在成千上万个谐波模式累加求和时，使用累加补偿量 $c$ 跟踪丢失的低位数字，能够在不增加显存带宽的前提下彻底杜绝精度损失。

## 3. CUDA 工程级加速实战

### 3.1 消除 cuBLAS 调度与同步开销
* **历史问题**：FEW 原有 `src/few/cutils/matmul.cu` 中，每次调用 `neural_layer` 时：
  1. `cublasCreate(&handle);` （开销极大，涉及系统调用与 CUDA Context 锁）；
  2. `cublasDgemm(...);`；
  3. `cudaDeviceSynchronize();` （强制排空 GPU 流，打破 CPU-GPU 异步重叠）；
  4. `cublasDestroy(handle);`。
  连续 21 层神经网络总计带来了高达数毫秒的虚耗！
* **优化范式**：
  * 将 `cublasHandle_t` 在模块初始化时持久化分配一次（如作为类成员或静态单例），全程复用；
  * 完全移除中间层间的同步屏障，所有操作在同一个 `cudaStream_t` 中顺序入队，让 GPU 的指令流水线完全饱和。

### 3.2 内存访问合并（Coalesced Memory Access）
* CUDA Warp（32 个线程）在同一时刻访问连续的 32/64/128 字节对齐显存地址时，硬件能够在一个内存事务中完成加载。
* **反模式**：跨步长过大的跳跃访问（如沿列优先数组的跨行访问）；
* **最佳实践**：调整插值系数表的数据排布（Layout Transformation），确保同一 Warp 内的线程读取相邻的网格点数据；对于常量或只读系数，使用 `const __restrict__` 修饰符让编译器生成 `LDG.E` 缓存加载指令。

## 4. 5GB Kerr 振幅表（`ZNAmps_...DS2Outer.h5`）的极限优化

### 4.1 现状痛点
* 数据文件尺寸：**5,089,095,248 字节（~5.09 GB）**。
* 包含 33 个离散的大黑洞无量纲自旋切片 $a \in [-0.99, 0.99]$。
* **原有机制**：在 `AmpInterpKerrEccEq` 构造时，通过 Python `h5py` 将全部 33 个自旋切片的全部 6993 个模式双三次插值系数一次性完全读入主机内存！
  * 冷启动加载耗时：**10 ~ 13 秒**；
  * 进程常驻内存（RSS）：**瞬间飙升至 6.5 GB+**。

### 4.2 终极解决方案：惰性分片加载（Lazy Slice Loading）与 LRU 缓存
* **物理事实**：对于任何一次特定的 EMRI 波形生成，中心大黑洞的自旋 $a$ 是固定已知的！双三次插值只需要在自旋网格中定位包含目标 $a$ 的那一个间隔，即**只需要相邻的 2 个自旋切片**（或者当自旋完全匹配时仅需 1 个切片）！
* **计算对比**：
  * 全量加载：33 个切片，5.09 GB 数据 I/O；
  * 惰性加载（HDF5 Hyperslab 局部切片读取）：2 个切片，仅需读取约 **308 MB**！
  * **冷启动时间预期可由 13 秒骤降至 0.5 秒以下，内存占用减少 90% 以上！**
* **多波形并发与 MCMC 友好**：配合一个容量为 4~6 的 LRU 自旋切片缓存，在连续采样相近自旋时，完全实现零磁盘 I/O。
